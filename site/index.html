release notes from your git log

Your changelog writes itself.

You ship constantly, but release notes are a chore — so the changelog goes stale and customers never hear about improvements. ShipNotes reads the commits since your last release and turns them into polished, customer-facing release notes. One command.

$ npx @mfmp17/shipnotes generate

Free & open source (MIT) · runs locally · no signup, no telemetry

How it works

No config files, no commit-message policing, no CI setup. If your repo has a git log, it works.

1

Point it at your repo

ShipNotes finds the commits since your latest release tag automatically — or any range you give it with --since-tag.

2

Commits become sections

Conventional commits and plain subject lines are sorted into Breaking Changes, Features, Fixes and Improvements. Version bumps, merges and chores are filtered out.

3

Ship it

Get clean Markdown for your CHANGELOG or a standalone HTML page ready to host — like the real example below.

The Claude rewrite pass

Grouping is free and runs offline. Add an Anthropic API key and ShipNotes also rewrites each entry the way you would for customers: benefit-first, duplicates merged, internal noise dropped. Here's the kind of difference it makes:

Your git log says

  • fix(billing): correct proration when upgrading mid-cycle
  • feat(exports): add CSV and Excel export for reports
  • perf: load the dashboard twice as fast on large workspaces

Your customers read

  • Upgrading mid-cycle now bills exactly the prorated amount — no more surprise charges.
  • Export any report to CSV or Excel with one click.
  • Dashboards on large workspaces now load about twice as fast.
